# Инструкции агента

## Назначение и границы

Китайская лексика из учебников и книги для чтения; генерация Markdown-карточек
для hashcards. Текущие переводы русские, но формат многоязычный. Общайся по-русски.
Для работы с VCS используй `jj`, а не команды `git`.
Не завершай коммиты, не переписывай историю, не перемещай bookmarks и не пушь без
явного разрешения. Автоматические снимки working copy в jj — обычная часть работы.
Сохраняй чужие изменения, включая новые и игнорируемые файлы, и исходные PDF.
Не управляй службами и не меняй настройки системы без отдельного разрешения.

## Единственный источник — TSV

- `1/<урок>/` — первая книга, уроки 1–14.
- `2/<урок>/` — вторая книга, уроки 15–26.
- `我一定要找到她…/` — книга для чтения.
- `words.tsv` — основные слова; `extra-words.tsv` — дополнительные.
- Редактируй эти TSV напрямую. Параллельных `.zh`/`.pinyin`/`.ru`, общего
  `book2-vocabulary.tsv` и промежуточного экспорта больше нет: не воссоздавай их.
- `1/5/words.zh.save` — оставленный старый вспомогательный файл, не действующий
  источник. Не импортируй и не удаляй его без запроса.

Формат: UTF-8, заголовок, разделитель — настоящий TAB, одна запись на строку,
завершающий перевод строки. Колонки строго в порядке:

```text
zh<TAB>pinyin<TAB><язык>...<TAB>pdf_page
```

Первые колонки — `zh`, `pinyin`, затем одна или несколько колонок перевода
(`ru`, `en`, `pt-BR` и т. д.) в любом порядке. `ru` не обязательна. Имена колонок
уникальны, непусты, без пробельных символов; `zh`, `pinyin`, `pdf_page` зарезервированы.
Китайский, пиньинь и все объявленные переводы обязательны в каждой строке,
без пустых значений и пробелов по краям. Частично заполненные языки не поддерживаются.
`pdf_page` — положительный физический номер страницы PDF (с 1), не печатный
номер. Если неизвестен — оставь поле пустым, не выдумывай. Генератор также
принимает заголовок без `pdf_page`. При наличии эта колонка всегда последняя.
Если номера неизвестны для всего файла (сейчас первая книга и «Бриз»), используй
заголовок без `pdf_page`, чтобы не создавать хвостовые TAB в каждой строке.
Пустые строки и TAB/переводы строк внутри полей запрещены. Кавычки — обычные
символы, не CSV-экранирование. Символ `|` теперь допустим: `paste` не используется.

Пиньинь — с Unicode-знаками тонов, не цифрами. Сохраняй порядок источника,
ненумерованные слова-компоненты и имена собственные; объединяй основные списки
диалогов одного урока, но держи дополнительные слова отдельно. Не удаляй повторы
автоматически: 得/de и 得/děi — разные записи. Примеры и метки частей речи не
переноси в словарные поля. Не переписывай личные пояснения пользователя без нужды.

## Генерация без промежуточных файлов

Основной пользовательский интерфейс — алиасы `.autoenv.zsh`: `gen-words`,
`gen-extra-words` и `ru-gen-*`. Не заменяй их прямыми вызовами uv в основном
сценарии документации; прямой CLI нужен для автоматизации и проверок.
Обычный сценарий использует плагин zsh-autoenv из личной конфигурации zsh:
вход в каталог проекта автоматически загружает разрешённый `.autoenv.zsh`,
выход из поддерева проекта запускает `.autoenv_leave.zsh` (при стандартной
обработке leave). Плагин может запросить повторное разрешение после изменения
файла. Не предлагай ручной `source` как обязательный шаг; это вариант без плагина
или для отладки. DevShell предоставляет zsh, но не настраивает личный плагин.

`gen-cards.py` — самостоятельный Python-скрипт с PEP 723-комментарием для uv.
Зависимостей, кроме стандартной библиотеки, нет.

```sh
uv run gen-cards.py --check 1/*/*.tsv 2/*/*.tsv 我一定要找到她…/*.tsv
uv run gen-cards.py 1/1/words.tsv                     # Markdown в stdout
uv run gen-cards.py 2/15/extra-words.tsv              # только дополнительные
```

`--lang <язык>` выбирает колонку ответа; по умолчанию при генерации — `ru`
для совместимости с существующими данными. Выбранная колонка должна быть во всех
входных файлах, иначе ошибка без частичного вывода и без подстановки другого языка.
`--check` без `--lang` проверяет все переводы, не требуя русского;
`--check --lang en` дополнительно проверяет наличие колонки `en`.
Все входы валидируются до вывода карточек. Ошибочные записи не пропускаются молча.
Файлы обрабатываются в переданном порядке, записи — в порядке строк TSV.
Скрипт ничего не записывает в репозиторий сам.

`.autoenv.zsh` определяет `gen`, `gen-card`, `gen-words`, `gen-extra-words`, `print-cards` и
`ru-gen-1-words`, `ru-gen-2-words`, `ru-gen-我一定要找到她…-words`.
`gen-words <язык> <каталог>...` читает `words.tsv` через Python. Без каталога берёт
текущий каталог. Книжные алиасы берут исходники относительно корня проекта,
а Markdown пишут в текущий каталог. `.autoenv_leave.zsh` очищает эти определения.
Общие функции не привязаны к языку; удобные алиасы `ru-gen-*` выбирают русский.

Формат карточек сохраняется:

```text
Q: 中文
A:

pīnyīn

перевод

---

```

Генерируй постоянные карточки только по запросу; уточняй, включать ли
дополнительные слова. Перед подключением autoenv прочитай shell-файлы.
Не объявляй алиасы проверенными без запуска в zsh.

## Карточки для печати

`print-cards.py` читает те же TSV через существующий валидатор, без Markdown.
В zsh-autoenv доступна функция `print-cards`, вызывающая скрипт через uv.
По согласованию с пользователем стандарт — квадрат 65×65 мм, A4, сетка 3×4
(12 карточек). Размер меняется через `--size-mm`; ряды и колонки рассчитываются
автоматически с внешними полями не менее 7,5 мм.

Лицевая сторона — только китайский и маленький номер в левом верхнем углу,
без подсказок с книгой, уроком, страницей или именем файла. На обороте — тот же
номер, пиньинь, выбранный `--lang` (по умолчанию ru) и источник мелким шрифтом.
У слов учебника единая нумерация через оба тома: уроки по возрастанию, основные
слова, затем дополнительные внутри урока, включая слова-компоненты. Номера
считаются по всем текущим TSV обоих томов, не по выбранному для печати поднабору;
том 2 сейчас начинается с №525. Изменение состава ранних записей сдвигает
последующие номера — это не постоянные ID. Для других источников, включая
«Бриз», используется порядковая нумерация в выбранном PDF.
Основные и дополнительные TSV подаются явно; ничего не подмешивай сам.
Пары страниц идут последовательно: лицо/оборот каждого листа. Колонки оборота
зеркалятся для двусторонней печати по длинному краю, включая пустые ячейки.

```zsh
print-cards --test-sheet -o calibration.pdf
print-cards 2/15/words.tsv --lang ru -o lesson-15-print.pdf
```

Печатать A4 portrait, actual size 100%, duplex long edge. Сначала физически
проверять нумерованный тестовый лист; PDF-тесты не доказывают совмещение принтера.
Есть `--back-offset-x-mm` (плюс вправо) и `--back-offset-y-mm` (плюс вверх).
Существующий PDF не перезаписывается. При непоместившемся тексте или недостающих
глифах выдаётся ошибка, а не обрезка/подмена символов.
Для китайского на лицевой стороне сначала уменьшай размер с 42 до 18 pt,
стараясь сохранить одну строку. Не переноси последний знак из четырёх ради
крупного шрифта. Многострочный вариант допустим, только если одна строка не
помещается даже при 18 pt. Переносы переводов на обороте этим не ограничены.

Первый запуск загружает закреплённый SHA-256 шрифт Noto Sans SC (~17 МБ, OFL)
в игнорируемый `.cache/print-cards/`; шрифт встраивается в PDF. Для офлайн-работы
можно передать `--font <TrueType.ttf>`, для другого кеша — `--font-cache`.
Не добавляй кеш/пробные PDF в Git. Существующие исходные PDF не трогай.

После изменений печатного генератора дополнительно запускай PDF-тесты с
зависимостями, а не полагайся на их skip в стандартном окружении:

```sh
uv run --no-project --with 'reportlab>=4.4,<5' --with 'fonttools>=4.58,<5' \
  --with 'pymupdf>=1.24,<2' python -m unittest -v test_print_cards.py
```

## Сканы и качество транскрипции

Ссылки на учебники, предоставленные пользователем:

- Том 1: https://www.phantastike.com/linguistics/novyiy_kurs_kitayskogo/pdf/
- Том 1, английская версия: https://www.acsu.nl/files/pdf/NewPracticalChinese/practicalchineseT1.pdf
- Том 2: https://ifiyak.sfu-kras.ru/sites/default/files/content/docs/centr%20kit%20yaz/Novyj%20prakticeskij%20kurs%20kitajskogo%20azyka.pdf

В ссылке на том 2 пробелы закодированы как `%20`. При сверке проверяй соответствие
издания локальному PDF; физические номера страниц могут отличаться.

```sh
uv run split-pdf.py --info
uv run split-pdf.py --pages 38-39,41-43 --format both --output <каталог>
```

По умолчанию источник — `NPKKYa_-_Uchebnik-2.pdf`, результат — PNG при 150 dpi.
Доступны `--format png|pdf|both`, `--dpi`, `--pages all`. Исходные PDF не меняются,
существующие результаты не перезаписываются. Скрипт также самостоятелен для uv.

Распознавай `生词` и `补充生词`, проверяя продолжения на следующих страницах.
Не подменяй распознавание угадыванием или автоматической генерацией пиньиня.
Сомнения сверяй с увеличенным изображением; неразрешённые — сообщай пользователю.
Непустой текстовый слой не гарантирует корректности: у PDF «Бриза» извлечённые
символы искажены. Ручная сверка Build — не независимая проверка.

Сохраняй переводы учебника; исправления предполагаемых опечаток отмечай отдельно.
Из известных исправлений: 棵/kē в `2/23/extra-words.tsv` (PDF 198, скан похож на
裸); 他/tā/он во втором диалоге урока 3 (PDF 50 первой книги, перевод в печати
ошибочно «она»). Не возвращай эти ошибки при механической сверке.
Новый подход к контекстным карточкам «Бриза» пока не согласован; не внедряй его
в рамках посторонних задач.

## Проверки

```sh
uv run gen-cards.py --check 1/*/*.tsv 2/*/*.tsv 我一定要找到她…/*.tsv
PYTHONDONTWRITEBYTECODE=1 uv run --no-project python -m unittest -v
jj status
jj diff --stat
```

Тесты проверяют состав TSV, формат, контрольные исправления и генератор.
Они не доказывают правильность распознавания по сканам. При изменении состава
слов обновляй контрольные количества только после сверки источника, не ради
прохождения тестов. Проверка shell-прослойки пропускается при отсутствии zsh;
явно отмечай такой пропуск. Используй разрешённый временный каталог для тестов.
Исполняемые скрипты именуй в kebab-case. Тесты остаются `test_*.py` для discovery
стандартного unittest; функции скрипта для тестирования доступны через `runpy`.

`flake.nix` предоставляет devShell с hashcards, uv и zsh: `nix develop`.
Hashcards берётся из `hashcards.packages.${system}.default` upstream-flake,
без копирования его сборки. Его nixpkgs следует корневому через `follows`;
версии входов фиксирует `flake.lock`. Неявный вход `flake-utils` у upstream
зафиксирован в его lock-файле и сам по себе не является ошибкой. После правок
Nix при наличии Nix проверяй `nix flake check` и
`nix develop -c hashcards --help`. Не устанавливай Nix и не меняй daemon без
разрешения; если проверка недоступна, отмечай это явно.

PDF, PNG и Markdown-карточки игнорируются VCS; `AGENTS.md` и `README.md` — исключения.
Не начинай отслеживать сканы и массовые артефакты принудительно. Проверяй
`jj status` и `jj diff`, включая добавленные файлы; учитывай, что игнорируемые
артефакты не входят в коммит. В итоговом ответе
перечисли результат, выполненные проверки и ограничения. Локальный фактический
handoff записывай в `HANDOFF.md`; старые результаты не выдавай за новые.
